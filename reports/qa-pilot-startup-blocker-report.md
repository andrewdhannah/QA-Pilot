# QA Pilot — Startup Blocker Report

**Generated:** 2026-07-02
**Trigger:** `start qa-pilot` (project selector protocol)
**Status:** Blocked — 4 structural issues prevent clean startup

---

## Summary

The `start qa-pilot` command ran the project selector protocol successfully (project found in index, identity/profile/status files loaded, pointer updated), but the **standard startup protocol** (Steps 4–6 of AGENT-START.md) failed because it was designed exclusively for The Librarian project. QA Pilot is a separate project type (Python/script-based, no web UI assets) and does not satisfy the hardcoded checks.

---

## Issue 1 — Level 2 Root Verification Checks Librarian-Only Files

**File:** `docs/rules/ACTIVE-REPO-ROOT-RULE.md` (§2.2, §2.3)

The root verification requires these files to exist at the project root:
- `Public/index.html`
- `Public/app.js`
- `Public/styles.css`
- `Public/theme.css`

These are The Librarian's web application assets. QA Pilot has no `Public/` directory — it is a Python/script-based QA framework.

**Impact:** Every `start <project-id>` for a non-Librarian project will fail this check.

**Resolution needed:** Generalize ACTIVE-REPO-ROOT-RULE.md to accept per-project verification criteria, or allow add-on projects to declare their own Level 2 verification file list.

## Issue 2 — STARTUP-STATE.md Is Librarian-Specific

**File:** `SessionStartup/STARTUP-STATE.md`

The generated startup state file hardcodes:
- `Project: The Librarian`
- `Active project root: /Users/andrew/Desktop/CarbideFrame/active/librarian`
- `Git branch: sprint-3`
- `Test baseline: 540`
- `Harness path: ...active/librarian/scripts/run-validation-harness.sh`

After the project selector switches to QA Pilot, this file is stale. It was generated by `scripts/run-startup-checks.sh` which runs from the Librarian project root.

**Impact:** No authoritative startup state exists for QA Pilot. The `Active project root` field in STARTUP-STATE.md (`active/librarian`) does not match the new edit root (`active/qa-pilot`), which per AGENT-START.md §4.2 would degrade the mode to `read-only`.

**Resolution needed:** Either (a) generate STARTUP-STATE.md from the selected project's root after project selection, or (b) make STARTUP-STATE.md project-agnostic.

## Issue 3 — No `scripts/run-startup-checks.sh` in QA Pilot

**File:** (missing) `active/qa-pilot/scripts/run-startup-checks.sh`

Step 5 of the startup protocol requires running this script from the project root. QA Pilot has no such startup check script.

**Impact:** Step 5 cannot execute. The startup protocol is incomplete for add-on projects.

**Resolution needed:** Create a QA Pilot startup check script, or allow the startup protocol to skip Step 5 when the script is absent for `harness_governed` projects.

## Issue 4 — AGENT-START.md §4.0 Hardcodes Librarian Project Layout

**File:** `SessionStartup/AGENT-START.md` (§4.0)

The Level 2 verification script in AGENT-START.md references file paths that only exist in The Librarian:
```bash
cd {{active_project_root}}
git branch --show-current
git status --short
test -f Public/index.html
test -f Public/app.js
test -f Public/styles.css
test -f Public/theme.css
```

This is not parameterized per project. Any project that doesn't have a `Public/` directory with those exact files will fail.

**Impact:** Can't cleanly start any non-Librarian project.

**Resolution needed:** Parameterize root verification so each project can declare its own required file checks, or add an exemption path for `harness_governed` add-on projects.

---

## Issue 5 — No PROJECT-STARTUP.md in QA Pilot

**File:** (missing) `active/qa-pilot/PROJECT-STARTUP.md`

The startup protocol Step 3 expects `PROJECT-STARTUP.md` at the active project root. QA Pilot uses `PROJECT-IDENTITY.md` instead (listed in its startup_files).

**Impact:** If the protocol strictly requires PROJECT-STARTUP.md, it would fail. Currently the project selector bypasses this by reading the project's declared `startup_files`, but after selection the standard protocol from Step 3 would look for PROJECT-STARTUP.md.

**Resolution needed:** Either create PROJECT-STARTUP.md for QA Pilot, or update the protocol to accept PROJECT-IDENTITY.md as a valid substitute for `harness_governed` projects.
