## 2. QA Trial Architecture

Two validation lanes executed in parallel:

- **Lane A (Fresh-install/fresh-agent):** Model an agent entering the workspace for the first time. Trace the exact file sequence. Verify historical complexity does not leak into ordinary operation.

- **Lane B (Upgrade/legacy-migration):** Model an organically evolved workspace with historical documents. Test whether migration creates competing active instructions.

Supplementary test suites: authority-resolution (7 scenarios), pre-execution readback (6 tests), LINK boundary (adversarial requests), capability posture, evidence/provenance, completion/acceptance, cold-storage/supersession, lifecycle projection (12 tests), comprehension trial.

## 3. Fresh-Install / Fresh-Agent Lane Results

### 3.1 Startup Path Trace

A fresh agent reads exactly **two files** during startup:

1. `/CarbideFrame/CLAUDE.md` (routing only — 33 lines)
2. `SessionStartup/startup-conformance-envelope.json` (generated by harness)

Then emits the pre-rendered receipt from `receipt_rendering.resolved_lines`.

**Assessment:** The startup path is clean and bounded. The harness executes all internal checks programmatically. The agent does not need to understand governance internals to start correctly.

**Finding F-003:** startup.json defines an old 9-step startup sequence that conflicts with the harness-based startup in CLAUDE.md. This file is not marked deprecated.

## 4. Upgrade / Legacy-Migration Lane Results

### 4.1 Competing Active Instructions

| Source | Competing Instruction | Resolution |
|--------|----------------------|------------|
| CLAUDE.md (active) | Run harness, read envelope, emit receipt | **Canonical** |
| CLAUDE.md.shim (stale) | Run harness, render from startup_report fields | Conflicts on receipt rendering |
| CLAUDE.md.pre-sse4a (stale) | Full old 10-step protocol, source authority model | Completely different startup |
| startup.json (active manifest) | Old 9-step filesystem-based startup | Conflicts with harness |
| active/librarian/CLAUDE.md | Defers to workspace-root, but contains intent routing table | Consistent but adds complexity |
| session-startup/STARTUP-PROTOCOL-V2 (never authorized) | Runtime-discovery-based startup | Never implemented, but present |

**Finding F-004:** The workspace has **six potential startup instruction sources** (3 CLAUDE.md variants + startup.json + active/librarian/CLAUDE.md + session-startup/v2). Only one is canonical. The others are not consistently marked as non-current.

### 4.2 Stale Doctrine Reachable as Normative

**Finding F-005:** STARTUP-OUTPUT-CONTRACT.md contains governance rules (candidate surfacing, post-startup receipt visibility, scope boundaries) with no active equivalent. The CLAUDE.md says "Do not read" this file, but the intent routing table in active/librarian/CLAUDE.md (line 78) references it as a source doc. This creates a direct conflict: the routing table says "read this" while the startup sequence says "do not read this."

### 4.3 Cold-Storage Material

Cold storage at `active/librarian/_archive/cold-storage/` contains 1,235 files. The material is properly archived but not sealed behind access controls. Key risks:

- `governance-contracts/` (9 files) — governance contracts that could be mistaken for current authority
- `workspace-rules/` (5 files) — rules that could be mistaken for active constraints
- `deprecated/` (3 files) — deprecated handoff files and stale startup state

**Finding F-006:** Cold-storage governance contracts and workspace-rules are not sealed. An agent following old instructions or resolving paths loosely could read them as normative guidance.

## 7. LINK Boundary Results

LINK boundary analyzed from AGENT-RUNTIME-BRIEF §7 and GOVERNANCE-REFERENCE Part 13.

LINK may: interpret, explain, recommend, frame work, bring Owner decisions forward.

LINK must not: grant authority, manufacture evidence, self-approve, self-seal, override Core, silently broaden scope, turn inference into canonical state.

**Finding F-007:** The LINK boundary is correctly defined in the active documents. No adversarial scenario tested produces a boundary violation. The critical rule — "LINK is advisory with respect to consequential authority" — is clear and unambiguous.

**Confirmed control:** LINK cannot grant authority even if asked. The Runtime Brief §7 explicitly states "You may not treat LINK output as authorization."
