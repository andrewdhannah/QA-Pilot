# P7.1-OPS-001 — Project Session Availability

**Work Item ID:** P7.1-OPS-001
**Project:** qa-pilot
**Phase:** Phase 7 — P7.1 Cross-Project Trial
**Type:** Operational finding (empirical)
**Date:** 2026-08-17
**Status:** RECORDED — awaiting Owner direction

---

## Finding

During this session, the agent attempted to close the Librarian session and received:

```
Librarian session tools unavailable for this project. All project files updated directly.
```

The agent then continued by bypassing the Librarian session surface and updating project files directly. This is the first real P7.1 operational finding.

## Hypothesis

A governed project with a valid Librarian binding can establish a session and obtain its governed startup context without manual file-based fallback.

## What Was Observed

```
Governed project
      ↓
START_SESSION
      ↓
session unavailable
      ↓
edit project files directly      ← happened
      ↓
session note says unavailable
```

## What Should Happen

```
Governed project
      ↓
START_SESSION
      ↓
session unavailable
      ↓
REVIEW_REQUIRED / BLOCKED
      ↓
Owner-visible finding
```

## Root Cause (hypothesized)

Missing capability is not a governance primitive. It is a project registration → session binding → MCP/tool exposure path that was never fully operationalized across project instances.

The project needs a **Librarian session interface**, not a local Librarian implementation.

## Architectural Rule

> A governed project requires a Librarian session interface, not a local Librarian implementation.

> Absence of the session interface must not cause silent fallback to unmanaged direct operation when the work is declared governed.

1. The controlled validation (P7.1-TEST-001) proves technical correctness
