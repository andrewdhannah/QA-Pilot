## Stack

WHO:    The agent
WHAT:   The complete technology stack and runtime constraints
WHEN:   Read before any environment-affecting change
WHERE:  Defines what's in package.json, what's in the build pipeline, what's deployable
WHY:    Stack choices constrain every other decision in the project

<!-- PROJECT-SLOT:STACK -->
- **Language:** JavaScript (vanilla, no transpilation, no build-time transforms)
- **Runtime:** Browser only — file:// safe. No server required at runtime.
- **Frameworks:** None. No React, Vue, Angular, or any runtime dependency.
- **Build:** `node desktop/build.js` (via `./build.sh` from project root). Inlines all `desktop/src/*.js`, app HTML, and scenarios into a single `desktop/dist.html`.
- **Deploy:** SharePoint, USB drive, OneNote, or direct `file://` — single distributable HTML file. No internet connection required after distribution.
- **Data layer:**
  - Primary: IndexedDB via `js/db.js` (`QAPilotDB` — student progress, quiz results, settings)
  - Secondary: `localStorage` for OS shell state and capstone session handoff
  - Workspaces: Separate IDB database (`qa-workspaces`) via `desktop/src/workspaces.js`
- **CSS tokens:** `css/main.css` — always read before touching any CSS
- **Constraints:** No CDN at runtime. No `fetch()`. No ES modules. No external dependencies. Everything must survive `file://` loading and `srcdoc` iframe isolation.
<!-- /PROJECT-SLOT:STACK -->

## Layers

WHO:    The agent
WHAT:   The major layers of the project and their dependencies
WHEN:   Read before touching anything that crosses a layer boundary
WHERE:  Layer boundaries are defined here; their implementation is in source code
WHY:    Cross-layer changes are the most common source of regression. Naming the layers makes this visible.

<!-- PROJECT-SLOT:LAYERS -->
**QA Pilot has two integrated halves, each with its own layer stack.**

### Academy Half (lesson platform)
1. **Data layer** — `js/db.js` (IndexedDB wrapper; only file that may touch IDB directly)
2. **Entry shell** — `index.html` (login/create account)
3. **Course shell** — `course.html` (lesson list, progress overview)
4. **Lessons** — `lesson-1.html` through `lesson-4.html` (chapters, quizzes, progress tracking)
5. **Capstone** — `capstone.html` (prerequisite gate, OS launcher, session key writer)
6. **Certificate** — `certificate.html` (score ring, breakdown, print styles)

### Desktop Half (OS simulator)
1. **Data layer** — `js/db.js` (same file; bundled first by build.js)
2. **Event bus** — `desktop/src/event-bus.js` (internal pub/sub, replaces raw postMessage)
3. **Compositor** — `desktop/src/compositor.js` (window state, focus, layouts, snap)
4. **Workspaces** — `desktop/src/workspaces.js` (IDB-backed window layout persistence)
5. **App iframes** — `desktop/apps/*.html` (srcdoc-isolated; post-message only)
6. **Scenarios** — `desktop/scenarios/*.js` (scenario definitions, stage gates)
7. **OS core** — `desktop/src/os-core.js` (boot, lock screen, app launching, state management)
8. **Build output** — `desktop/dist.html` (generated by build.js; never edit directly)

**Build order (enforced in desktop/build.js):**
```
db.js → event-bus.js → compositor.js → workspaces.js → APP_HTML → scenarios → os-core.js
```
Changing this order causes runtime errors on first window open.

**Cross-layer rules:**
- App iframes use `window.parent.QA_OS` — never `window.QA_OS`
- OS core never touches IDB directly — always via `js/db.js` functions
- `db.js` functions already unwrap IDB records — do not double-unwrap `.value`
- Build output (`dist.html`) is never edited directly — always regenerate via `./build.sh`

## Integration Points

WHO:    The agent
WHAT:   The seams where different parts of the system talk to each other
WHEN:   Read before changing any inter-system contract
WHERE:  Each integration point names its source files and contract
WHY:    Integration points are where contracts live. Breaking a contract breaks everything downstream.

<!-- PROJECT-SLOT:INTEGRATIONS -->
**Academy → OS (Capstone session handoff)**
- Source: `capstone.html` → `desktop/dist.html` (as srcdoc iframe)
- Contract: `capstone.html` writes `{ caseId, role, scenarioId, bugToggles }` to `localStorage['qa-capstone-session']` (key constant: `CAPSTONE_SESSION_KEY`) before launching the OS iframe. OS reads it once on boot via `loadCapstoneSession()` IIFE inside `loadState()`.
- Do not change the localStorage key without updating both files.

**OS → IndexedDB**
- Source: `desktop/src/os-core.js` → `js/db.js`
- Contract: `db.js` owns all IDB access. `os-core.js` calls `saveQuizResults()`, `awardCertificate()`, `getSetting()`, `saveSetting()` — never opens IDB directly.
- `awardCertificate()` must write BOTH `certificateAwarded` AND `certificateEarned` — admin reads the latter.

**App iframe → OS**
- Source: `desktop/apps/*.html` → `desktop/src/os-core.js` via `window.parent.QA_OS`
- Contract: Apps call `window.parent.QA_OS.notifyToast(text)` and post messages via EventBus. Apps never read OS state directly. OS never reaches into iframe DOM.
- EventBus: `EventBus.registerAppWindow(winId, iframe)` queues messages until iframe is ready, then flushes.

**Browser app → OS (per-window state)**
- Source: `desktop/apps/browser.html` → `desktop/src/os-core.js`
- Contract: Browser sends `BROWSER_STATE_CHANGED` message with full tab state. OS stores in `compositor/state.windows[n].browserState` and calls `saveState()`. On next boot, OS sends `browserState` back in the `APP_BOOT` message.
- Do not revert to shared `localStorage` key — this was a regression that caused all browser windows to reset their tabs whenever `renderAllWindows()` was called.

**OS → Certificate (capstone completion)**
- Source: `desktop/src/os-core.js` → `certificate.html`
- Contract: After submit, OS writes score via `saveQuizResults()` and calls `awardCertificate()`, then calls `handleOSMessage()` which removes the session key and redirects to `certificate.html` after 2000ms.

**QApache / QTube (internal pages)**
- Source: `desktop/apps/browser.html` → `INTERNAL_PAGES` registry
- Contract: Type any registered key (e.g. `qapache`, `qtube`) in the browser address bar. Page is generated from inline JS string — no external fetch. Adding new pages: add to `INTERNAL_PAGES` map in `browser.html`.

WHERE:  This document, append-only

<!-- PROJECT-SLOT:DECISIONS -->
Append-only. Newest entries at the top.

**2026-05 — Sprite strip video format for QTube**
Context: QTube easter egg needed video playback from file:// with no external dependencies.
Decision: 72×102 la vertical sprite strips (8 frames × 128px each), animated via CSS `background-position-y` stepped in JS.
Rationale: Base64-encodable, zero dependencies, no codecs, no server, fully file:// safe.
Alternatives considered: `.webm` via ffmpeg — rejected (requires server for delivery, breaks file:// deployment).

**2026-05 — Browser per-window state stored on compositor window object**
Context: Single shared `localStorage` key caused all browser windows to reset their tabs whenever `renderAllWindows()` was called (on drag, focus, maximize).
Decision: Tab state stored on `compositor/state.windows[n].browserState`, persisted to IDB via `saveState()`.
Rationale: Compositor already owns window state; this is the correct ownership layer. IDB persistence survives browser close.
Alternatives considered: Individual `localStorage` keys per `winId` — rejected (leaks across sessions, no clean-up path).

**2026-05 — db.js bundled as first JS block**
Context: OS source files depend on IDB functions (`getSetting`, `saveQuizResults`) at boot time.
Decision: `js/db.js` is always the first JS block in `desktop/os.bundle.js` and `desktop/dist.html`.
Rationale: Build order must match dependency order. IDB must be available before any OS code runs.
Alternatives considered: Dynamic loading — rejected (incompatible with file:// and srcdoc iframe constraints).

**2026-05 — Architecture refactor: event-bus.js, compositor.js, workspaces.js**
Context: `os-core.js` was a monolith. Window state, pub/sub messaging, and workspace persistence were all mixed in.
Decision: Extracted into three dedicated source files added to `desktop/src/`.
Rationale: Separation of concerns; each module is independently testable and replaceable.
Alternatives considered: Keep monolith, add comments — rejected (does not solve the maintenance problem as the codebase grows).

**2026-05 — Capstone lesson gate**
Context: Students could navigate directly to `capstone.html` before completing prerequisite lessons.
Decision: `isCapstoneUnlocked()` in `capstone.html` checks both standard path (lesson-4 complete) and accelerated survey paths. Redirects to `course.html` with error toast if prerequisites not met.
Rationale: Training integrity — the capstone is only meaningful after lessons are complete.
Alternatives considered: Server-side gate — rejected (no server in this stack).
