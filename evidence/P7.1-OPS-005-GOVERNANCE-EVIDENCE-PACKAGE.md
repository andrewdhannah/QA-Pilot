### Schema Conformance Analysis

The 12 receipts declare schema `owner-decision-custody-receipt-v1`. This schema:
- Is referenced in the receipts themselves
- Has NO corresponding schema file in `docs/schemas/`
- Is NOT the same as `qa-pilot-receipt.schema.json`

When validated against `qa-pilot-receipt.schema.json` (the general receipt schema), all 12 fail because they're a different receipt type with different required fields.

### Authority Verb Analysis

The receipts contain authority verbs in their content:
- "approve" — appears in `decision_type: "approved"` and `enforcement.decision` fields
- "seal" — appears in `sealed_contracts_referenced` field
- "mutate" — appears in `mutation_status` field

**Classification:** These verbs describe **decisions that were made** (past tense), not **actions the receipt is executing** (imperative). The receipt records that the Owner approved/denied a write. The receipt itself does not approve, seal, or mutate anything.

## Decision Options

### Option A: Accept As-Is

**Rationale:** The owner-decision-custody receipts are a distinct receipt type with their own schema. They serve a different purpose than general QA Pilot receipts. The missing schema file is a documentation gap, not a conformance failure.

**Action:** Create `docs/schemas/owner-decision-custody-receipt.schema.json` to document the existing structure.

**Risk:** Low. Documentation only. No receipt mutation.

### Option B: Remediate to General Schema

**Rationale:** All receipts should conform to the general QA Pilot receipt schema for consistency.

**Action:** Transform 12 receipts to add missing fields from `qa-pilot-receipt.schema.json`.

**Risk:** Medium. Mutates historical receipts. May break existing consumers.

### Option C: Deprecate and Replace

**Rationale:** The owner-decision-custody receipt type is from an early project phase. Replace with current receipt types.

**Action:** Archive old receipts, mark as deprecated.

**Risk:** High. Loses historical decision trail.

---

## Evidence-Based Recommendation

The governance evidence reveals:
1. A documentation gap (missing schema file) — **Option A** addresses this
2. The receipts are a distinct type, not non-conformant — **Option B** is inappropriate
3. The receipts are historical and functional — **Option C** is excessive

**Recommended: Option A** — Accept as-is, document the schema.
