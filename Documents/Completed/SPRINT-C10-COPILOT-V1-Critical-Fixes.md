## Bug 1 — CRITICAL: Scoring engine not bundled

### Root cause
`desktop/src/scoring.js` defines `window.evaluateSubmission` — the function the OS calls
when the trainee submits their findings. But `build.js` never reads or includes `scoring.js`.
At runtime, `window.evaluateSubmission` is `undefined`, so `runSubmit()` hits this guard
and returns immediately:
```javascript
if (!window.evaluateSubmission) {
  addNotification("Scoring engine not loaded.");
  return;
}
```
The trainee sees a notification but no result. The scoring, modal, IndexedDB write, and
CAPSTONE_COMPLETE signal never fire.

### Fix: Add `scoring.js` to `build.js`

In `desktop/build.js`, add a path constant and include `scoring.js` in both outputs.

**Step 1 — Add the path constant** (after the existing path constants near the top of the file):
```javascript
const SCORING_PATH = path.join(ROOT, "src", "scoring.js");
```

**Step 2 — Read the file in `build()`** (after the existing `readArchLayer` calls):
```javascript
const scoringJs = fs.existsSync(SCORING_PATH)
  ? fs.readFileSync(SCORING_PATH, "utf8") + "\n"
  : "// scoring.js not found — scoring disabled\n";
```

**Step 3 — Add `scoringJs` to the bundle content** (in the `bundleContent` string,
add it AFTER `wrappedCore` — scoring must come after os-core.js so the OS is
initialised first):
```javascript
const bundleContent =
  "// os.bundle.js — generated by build.js — do not edit by hand\n\n" +
  dbJs        + "\n" +
  eventBusJs  + "\n" +
  compositorJs+ "\n" +
  workspacesJs+ "\n" +
  appHtmlDecl + "\n" +
  scenariosJs + "\n" +
  wrappedCore + "\n" +
  scoringJs;          // ← ADD THIS LINE (scoring after os-core so QA_OS exists)
```

**Step 4 — Add `scoringJs` to the `safeJs` variable** (for `dist.html` output):
Find the line that builds `safeJs` — it concatenates all the modules. Add `scoringJs`
at the end of the concatenation, after `wrappedCore`:
```javascript
const safeJs = (dbJs + "\n" + eventBusJs + "\n" + compositorJs + "\n" +
                workspacesJs + "\n" + appHtmlDecl + "\n" + scenariosJs + "\n" +
                wrappedCore + "\n" + scoringJs)   // ← add scoringJs here
  .replace(/<\/script/gi, "<\\/script");
```

**Do not modify scoring.js itself.**

## Bug 2 — HIGH: Right-click context menu never dismisses

### Root cause
`setupDesktopContextMenu()` creates a `.qa-context-menu` element and appends it to the
document when the user right-clicks the desktop. Clicking a menu item removes the menu.
But clicking ANYWHERE ELSE does not remove it — there is no click-away dismiss handler.
The `document.addEventListener("click")` in `bindEvents()` handles the start menu,
quick panel, and notify centre, but has no case for `.qa-context-menu`.

### Fix: Add dismiss logic in `src/os-core.js`

**Option A (preferred) — Add to the existing global click handler in `bindEvents()`:**

Find the `document.addEventListener("click", ...)` block in `bindEvents()`.
Inside it, add a line to remove any open context menu when the user clicks anywhere:

```javascript
document.addEventListener("click", (e) => {
  // Dismiss any open context menu on any click outside it
  var openMenu = document.querySelector(".qa-context-menu");
  if (openMenu && !openMenu.contains(e.target)) {
    openMenu.remove();
  }

  // ... existing code for start menu, quick panel, notify centre ...
  if (!startMenu.contains(e.target) && !startButton.contains(e.target)) {
    hideStartMenu();
  }
  // ...
});
```

Place the context menu dismiss check as the FIRST thing inside the click handler
so it fires before the other checks.

**Also add dismiss on `Escape` key:**

Find the `document.addEventListener("keydown", ...)` block (it currently just unlocks
the lock screen). Add a context menu close:

```javascript
document.addEventListener("keydown", (e) => {
  // Close context menu on Escape
  if (e.key === "Escape") {
    var openMenu = document.querySelector(".qa-context-menu");
    if (openMenu) { openMenu.remove(); return; }
  }

  // ... existing keydown logic ...
  if (!lockScreen.classList.contains("qa-lock-hidden")) unlock();
});
```

## Bug 3 — HIGH: Start menu search input not auto-focused

### Root cause
When the Start menu opens (`toggleStartMenu()`), `startSearchInput` is never focused.
The user opens Start and starts typing, but keyboard input goes nowhere because focus
is on whatever element was last active.

### Fix: Focus the input on Start menu open, clear it on close

In `src/os-core.js`, find the `toggleStartMenu()` function.
After the code that shows the start menu, add:

```javascript
function toggleStartMenu() {
  var isHidden = startMenu.classList.contains("qa-start-menu-hidden");
  if (isHidden) {
    startMenu.classList.remove("qa-start-menu-hidden");
    // Focus the search input after a short delay so the menu animation completes
    if (startSearchInput) {
      setTimeout(function() { startSearchInput.focus(); }, 80);
    }
  } else {
    hideStartMenu();
  }
}
```

Find `hideStartMenu()` and add input clear + reset:

```javascript
function hideStartMenu() {
  startMenu.classList.add("qa-start-menu-hidden");
  // Clear search input and reset the app grid to show all apps
  if (startSearchInput) {
    startSearchInput.value = "";
  }
  renderStartMenu();  // reset filter — if this call already exists, keep only one
}
```

**Check the existing implementations of `toggleStartMenu()` and `hideStartMenu()` first.**
Add only the missing lines — do not rewrite the functions from scratch.

## Bug 4 — MEDIUM: Dynamics CRM BUG_FOUND not triggered on form load

### Root cause
The `status-junior-escalated` bug detection only fires when the Status dropdown
`change` event fires. But when `populateCaseForm()` pre-loads a scenario where
Status is already set to "Escalated" (e.g. `case-002`), no `change` event fires
and the bug is never detected.

### Fix: Call status check after form population in `apps/dynamics.html`

In `apps/dynamics.html`, find `populateCaseForm()`. At the very end of the function,
after all fields are set, add a call to check for the pre-loaded violation:

```javascript
function populateCaseForm(crmState) {
  // ... existing field population code ...

  // Check for bugs that may be pre-loaded in the scenario data
  // (these fire immediately on form load, not waiting for user interaction)
  checkStatusViolation();
}
```

If `checkStatusViolation()` doesn't already exist (it was specified in C-9 but may not
be merged yet), implement a minimal version:

```javascript
function checkStatusViolation() {
  var statusEl = document.getElementById("dyn-status");
  if (!statusEl) return;

  var val        = statusEl.value;
  var restricted = ["Closed", "Escalated"];

  if (currentRole === "junior" && restricted.indexOf(val) !== -1) {
    window.parent.postMessage({
      type:  "BUG_FOUND",
      bugId: "status-junior-" + val.toLowerCase(),
    }, "*");

    var OS = window.parent && (window.parent.QA_OS || window.parent.OS);
    if (OS && OS.notify) {
      OS.notify("⚠ Case Status \"" + val + "\" is not permitted for Junior role (AC-2.1).");
    }
  }
}
```

**Read the existing `dynamics.html` before writing.** Match the existing variable names
(`currentRole`, field IDs) exactly. Do not duplicate if `checkStatusViolation` already exists.
